# Products 與 Buying tools：買家需求與視覺複核

2026-10-02；ThinkPad 本機草稿；實際 Chrome 在 1440px 與 375px 檢視，並操作產品選擇、詢價清單與成本工具。沒有遠端發布。

## 判斷

Products 以選品、看規格與建立詢價清單為主。Buying tools 以買家自行輸入假設的成本與毛利試算為主。資訊有幫助的判準是：能否讓買家判斷產品是否符合需求，或完成下一個採購步驟。沒有使用量資料，不能斷言新聞或市場比較沒有人使用；因此保留直接網址，改為參考層級。

## 原畫面與本次改動

| 發現 | 本次處理 | 買家與工程上的理由 |

| 手機上先看到長段市場、棧板、法規及成本說明 | 市場與包裝說明改為可展開，縮短開場 | 先找產品，再按市場需求查細節；保留既有資料來源與選擇 |
| 手機產品詳細資料在整份清單之後，原量測位置約 11,048px | 1080px 以下以原生 dialog 立即顯示規格；返回或 ESC 回到選品位置 | 修正操作阻塞；瀏覽器負責焦點限制與鍵盤關閉，不引入 UI 套件或後端 |
| TW/CN 成本指數與五點適配評分占據每列空間 | 從選品畫面與詢價文字移除；原資料保留 | 指數不能代替 SKU 報價，評分未向買家說明依據；詢價改成 SKU、品名、產地、數量 |

## 工程邊界

- 沒有刪除 SKU、修改材質規格、計算公式或新增報價。
- 原 catalog localStorage 選擇與詢價清單仍可讀取；市場與 DIY/Professional 切換維持。
- 各工具的既有 URL、hash 與搜尋索引保留；產品製程仍在原詳細區。
- 工具層級放在 `config/routes.json`；新文字在 `config/languages.json`，十語言同步。
- 原生規格視窗重用現有詳細 DOM，關閉及跨至桌面寬度時還原位置。清單重新渲染後，以選中 SKU 回復焦點。
- 無資料庫、會員、新排程、外部寫入或訊息通知；service worker 升至 v62。

## 驗證

`npm run build`、`npm run check`、`npm test` 通過；原測試維持 12 個公開頁 × 375/1280px 與十語言。新增：產品指數/評分/占位入口不存在、市場說明預設收合、手機即時規格視窗、ESC 關閉與焦點返回、工具入口層級、詢價剪貼簿文字不含成本指數。

## 後續優先方向

1. 把產品清單帶入聯絡頁的詢價草稿，減少複製與貼上。採同瀏覽器儲存與使用者主動建立郵件，不新增伺服器保存或自動寄信。
2. 成本頁先顯示貨值、數量、目的地、運費與總成本；稅費細項、零售毛利、產地比較按需展開。顯示範例輸入與來源，維持可編輯假設及既有計算公式。
3. 產品頁補充分清楚的實際供應與客製範圍；MOQ、交期只在有可靠資料時顯示。通用市場敘述和參考製造選項不應暗示為確認的 SKU 承諾。
4. 為主力產品加入已有、經確認的實物圖片。先提高辨識與規格可信度，再考慮增加推薦、比較或其他互動。

這些後續方向不假設所有買家都要用市場研究工具，也不要求固定人工內容更新；優先改善詢價完成率與回訪時重用既有選擇。
